# 노트 작성 형식

AI에게 노트를 만들게 할 때 함께 넘기는 형식 규칙

---

## 파일

- 위치: `android/<분류>/` (예: `android/kotlin/`)
- 파일명: 제목에서 뽑은 **한글-하이픈** 이름, 날짜 없음
  - 예: `코틀린-확장함수-기본문법과-동작규칙.md`
- 한 파일은 250줄 이하 → 넘으면 `…-응용문법.md`처럼 나눔
- 파일 첫 줄은 제목, 날짜·분류 줄은 쓰지 않음

## 제목

```
# 주제: 세부 내용 (영어 용어)
```

- 예: `# 코틀린 확장 함수: 기본 문법과 동작 규칙 5가지 (Extension Functions)`

## 구성 순서

1. 기본 문법 또는 핵심 개념
2. 동작 원리 (`javap`, 디컴파일 등 직접 확인하는 방법 포함)
3. 규칙·특징 (항목마다 코드 1개 + 핵심 2~3줄)
4. 만들기 전에 확인 (표준 라이브러리, Android KTX에 이미 있는지)
5. Android 예제
6. 주의할 점
7. 참고 자료

## 문장과 코드

- 본문은 한글, 코드와 용어는 영어
- 문장은 명사형 종결 (`~함`, `~임`, `~가능`, `~불가`)
- "쉽게 말하면" 같은 덧붙임 없이 제목 아래에서 바로 코드 → 항목 순서
- 코드는 ```` ```kotlin ```` 블록, 결과는 `// 결과` 주석
- 실행되는 예제는 `fun main()`을 포함해서 그대로 복사해 실행 가능하게 작성
- 컴파일 에러를 보여 줄 때는 `// 컴파일 에러: <실제 에러 문구>` 형식
- Android 전용 코드는 실행 검증에서 제외되므로 "실행 안 됨"이 정상

## 검증

예제는 노트에 적기 전에 실제로 실행해서 주석과 대조

```
KOTLIN_HOME=<kotlinc 설치 폴더> python -I tools/verify_notes.py <임시 폴더> android/kotlin/*.md
```

- 노트의 ```` ```kotlin ```` 블록을 추출해서 블록별로 컴파일·실행
- 실행된 예제의 출력과 `// 결과` 주석이 다르면 노트를 고침
- `<임시 폴더>/report.json`에 블록별 결과 저장

## 출처

- 공식 문서 예제를 가져오거나 변형했으면 참고 자료에 명시
- Android API 이름은 소스나 공식 문서에서 확인한 것만 사용
